# FinAssist Finance Advisor - Orchestration & Workflow Refactor

## Objective

Refactor the Finance Advisor architecture to create a scalable, workflow-agnostic, multi-agent system that correctly handles:

* Financial advice

* Expense predictions
* RAG retrieval
* SQL transaction analytics
* Human-in-the-loop workflows
* Context switching
* Slot filling

Examples in this document are illustrative only and must not influence routing logic.

# Current Architectural Issues

The current system exhibits the following failures:

### Workflow Leakage

An active workflow consumes unrelated future messages.

Expected behavior:

* Active workflow should not automatically own every incoming message.
* Each incoming message must be re-evaluated.

---

### Retrieval Dependency Failure

Financial advice currently fails when retrieval returns no documents.

Expected behavior:

* RAG enriches responses.
* RAG does not gate response generation.

---

### Slot Persistence Issues

Information already provided by the user is being requested again.

Expected behavior:

* Previously collected information must be persisted and reused.

---

### Workflow Isolation Issues

Questions from one workflow appear inside unrelated workflows.

Expected behavior:

* Workflow definitions remain isolated.
* Questions originate only from the active workflow.

---
